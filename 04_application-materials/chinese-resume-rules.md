# 中文简历生成规则

本文件是 Agent 生成和检查中文简历时必须执行的规范。默认输出为一页 A4、单栏、可复制文字的 HTML 简历。`templates/resume-zh.html` 是结构母版，`templates/resume-zh-reference.docx` 是设计岗位的版式参考。两份模板里的示例和占位文字都不是使用者经历。

## 一 输入与事实边界

1. 个人信息只能来自 `01_profile/` 中由使用者填写并确认的非 `.example.md` 文件。
2. 岗位要求只能来自使用者提供或 Agent 保存的真实 JD。记录公司、岗位、来源、获取日期和原文，不根据岗位名称猜职责。
3. 缺失的学校、学历、时间、职责、工具、证书、项目状态和结果数据必须标记为“待用户补充”，不得补写成看似合理的内容。
4. 允许润色句子、调整顺序、压缩弱相关内容和突出真实贡献；不得把协助写成主导、把概念方案写成已落地、把团队成果全部归为个人。
5. 近似数据只有在使用者能解释来源和口径时才可写，并用“约”“近”“超过”等限定词。无法说明依据时改写为真实交付物，不自行创造百分比。
6. `templates/resume-zh-reference.docx` 中的姓名、学校、组织、数据和项目全部为虚构示例，禁止复制到真实简历。

## 二 生成前必须完成的分析

生成简历前先输出“JD 要求—经历证据—缺口”对照表：

| 项目 | 要求 |
|---|---|
| JD 要求 | 使用 JD 原文或忠实概括，标注优先级 |
| 经历证据 | 指向 `01_profile/` 的具体文件和事实 |
| 匹配程度 | 强匹配、中等匹配、弱匹配或无证据 |
| 处理方式 | 突出、保留、压缩、删除或待补充 |

先选择最能证明岗位核心能力的经历，再开始写简历。关键词只有在真实经历能够支撑时才自然使用，不为了 ATS 堆词。

## 三 内容结构与排序

应届生默认顺序如下，可根据 JD 调整“实习经历”和“项目经历”的先后与篇幅：

1. 基本信息：姓名、电话、邮箱、已确认的作品集或个人网站。
2. 教育经历：学校、专业、学历、起止时间；成绩、排名、课程和奖项只在有依据且对岗位有帮助时保留。
3. 实习或工作经历：优先保留与岗位职责直接相关的经历。
4. 项目经历：优先展示能证明目标能力、方法和交付物的项目。
5. 专业技能：按“工具—方法—语言或证书”组织，只写能够在面试中解释或演示的内容。
6. 自我评价或求职摘要：可选。只有能提供新增信息时保留，不重复技能表，不写“学习能力强、认真负责”等无证据套话。

同一经历保留 2–4 条要点。强相关经历可占 3–4 条，弱相关经历压缩到 1–2 条或删除。经历多时优先删除与 JD 无关的课程、空泛自评和重复技能，不通过无限缩小字号塞进一页。

## 四 标题 日期和基本信息

- 姓名使用真实中文姓名；如投递要求英文名，可在姓名后以括号补充，不自行创造英文名。
- 电话和邮箱必须来自事实库。公开作品集链接先验证可访问，并确认不暴露不应公开的信息。
- 照片默认不放。只有使用者主动提供并确认、且目标地区和岗位适合使用照片时才加入。
- 日期统一为 `YYYY-MM ~ YYYY-MM`，在读或在职可写 `YYYY-MM ~ 至今`。全文不得混用 `2025.03`、`2025/03`、中文年月等格式。
- 经历标题推荐格式为 `组织或项目名称｜岗位或角色`。角色必须准确，不把课程作业写成商业项目。
- 日期位于标题行最右侧并禁止换行；标题过长时先缩短非必要描述，不挤压日期栏。

## 五 要点写作规则

每条要点优先采用以下结构：

> 本人动作 + 工作对象或方法 + 可核实的交付物、变化或结果

示例结构，不可直接当作经历使用：

- “访谈 8 名目标用户并整理高频痛点，形成需求优先级和设计约束。”
- “使用 Rhino 完成三版结构方案，比选后输出效果图、爆炸图和尺寸说明。”

具体要求：

1. 用“调研、分析、设计、建模、测试、协调、整理、交付”等具体动词开头，减少单独使用“负责、参与、协助”。如果事实确实只是协助，应保留协助边界并写清本人完成的部分。
2. 一条要点只表达一个主要贡献。不要把调研、建模、营销、汇报和结果全部塞进一个长句。
3. 优先写岗位需要的动作和交付物，而不是介绍项目背景。背景通常控制在一句内。
4. 数字必须附带口径，例如样本量、周期、数量、转化对象或比较基准。不要使用“提升 30%”但不说明什么指标、哪段时间、与什么比较。
5. 团队项目写明本人负责的模块；如果结果属于团队，使用“与团队完成”“支持”“参与交付”等准确表达。
6. 概念设计、课程项目、竞赛稿和未落地方案必须写明真实状态。
7. 每条建议 26–55 个中文字符，通常不超过两行。出现只有 1–3 个字的短尾行时，优先精简或重组句子。
8. 不重复同一个动词和同一项工具。工具应放在证明能力的位置，而不是每条都罗列软件名。

## 六 HTML 版式合同

生成文件必须从 `templates/resume-zh.html` 复制，不覆盖母版。除非内容经过删减仍无法合理排版，否则保留以下默认值。

| 元素 | 默认值 | 允许范围或要求 |
|---|---:|---|
| 页面 | A4 纵向 `210mm × 297mm` | 只允许一页；不得改为 Letter |
| 打印页边距 | `@page { margin: 0; }` | 浏览器打印时关闭页眉页脚 |
| 内容安全边距 | `.page { padding: 6mm; }` | 四边不得小于 `5mm`；推荐保持 `6mm` |
| 正文字体 | `10.3pt` | 最低 `9.5pt`，不得为了塞内容继续缩小 |
| 正文行高 | `1.44` | 可在 `1.35–1.48` 内微调 |
| 姓名字号 | `22pt`，行高 `1.15` | 建议 `20–24pt` |
| 联系方式 | `9.5pt` | 保持单行或两行，链接不得与头像重叠 |
| 页首下间距 | `13pt` | 可在 `10–14pt` 内调整 |
| 模块上间距 | `13pt` | 默认 `13pt`；页面紧张时最低 `9pt` |
| 模块标题 | `12pt`，行高 `1.2` | 下边距 `6pt`，下内边距 `3pt`，底线 `1pt` |
| 单条经历下间距 | `8pt` | 可在 `6–10pt` 内调整 |
| 标题与日期间距 | `8pt` | 日期列使用 `white-space: nowrap` |
| 经历标题 | `10.5pt` 加粗 | 不低于正文大小 |
| 日期 | `9pt` | 统一格式，不换行 |
| 要点列表上间距 | `3pt` | 左缩进 `1.25em` |
| 单条要点间距 | `1pt` | 可在 `0.5–2pt` 内调整 |

字体栈保持为：`"MiSans", "Microsoft YaHei", "PingFang SC", Arial, sans-serif`。正文颜色保持高对比度；链接可使用模板深蓝色。不要使用浅灰正文、渐变、复杂背景、进度条式技能图或装饰性图表。

## 七 空间不足时的处理顺序

出现第二页、底部溢出或内容过密时，必须按以下顺序处理：

1. 删除与 JD 弱相关的经历、课程、自评和重复技能。
2. 将长背景句改为动作与交付，合并重复信息，消除短尾行。
3. 把弱相关经历从 3–4 条压缩为 1–2 条。
4. 在允许范围内减少模块间距、经历间距和要点间距。
5. 在允许范围内小幅降低行高。
6. 最后才可将正文从 `10.3pt` 调到最低 `9.5pt`。

不得通过负边距、缩放整页、隐藏溢出文字、重叠文本框或小于 `5mm` 的安全边距强行做成一页。如果一页仍装不下，应让使用者选择删减内容或明确改为两页。

## 八 分页和打印规则

- `section` 和 `.entry` 使用 `break-inside: avoid`，不得把一个经历标题与其第一条要点拆开。
- 页面内容不得超出 `.page` 的 A4 高度。不要只看浏览器窗口，必须检查打印预览。
- 打印设置：A4、纵向、缩放 100%、边距无、关闭页眉页脚、启用背景图形。
- PDF 必须只有一页，正文文字可以选中复制，链接可点击或至少显示完整地址。
- 页面底部应保留约 `5–8mm` 的安全空白；不得让最后一行贴到纸边。
- 检查头像、长链接、日期和长学校名是否与其他元素重叠。

## 九 交付前检查清单

- [ ] 所有个人事实均能追溯到 `01_profile/`，所有 JD 判断均能追溯到真实 JD。
- [ ] 模板中的方括号、虚构姓名、示例学校、示例电话和示例项目已全部替换或删除。
- [ ] 重要 JD 关键词都有事实证据，没有关键词堆砌。
- [ ] 每条要点写清本人动作，没有夸大职责、项目状态或数字。
- [ ] 日期格式、标点、全角与半角空格一致。
- [ ] 无错别字、无重复句、无孤立标题、无明显短尾行。
- [ ] 打印预览为一页 A4，页面无裁切、重叠和第二页空白。
- [ ] PDF 文字可选择复制，作品集和个人网站链接正确。
- [ ] 文件保存到 `04_application-materials/pending-review/公司-岗位/`，未覆盖母版。
- [ ] 最终版本已经交给使用者审核；未经确认不得用于投递。
